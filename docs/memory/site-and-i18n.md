# The site: pages, languages, SEO, measurement

Read before touching `src/pages/`, `src/layouts/`, `src/components/` (but the player), `src/i18n/`, `src/content/`, `src/lib/{routes,seo,markdown,git,audience*}.ts`, `scripts/build-og-images.mjs` or `src/styles/global.css`.

## Languages (2026-10-19, read off the code)

- French is `defaultLang`, served at `/`; `en` and `it` are prefixed (`astro.config.mjs`, `prefixDefaultLocale: false`). **Every language uses the French slugs** (`/en/biographie`, `/it/theorie/introduction`): `neutralPath` / `localizedPathname` in `src/lib/seo.ts` only add or strip the language prefix, and `LanguagePicker.astro` swaps it on the current path. Keep it that way, or make the slug map one module every one of those reads.
- Interface strings: `src/i18n/ui.ts`, one object per language typed from the French keys (`UiKey`). `useTranslations` falls back to French for a missing key **in silence** — a forgotten Italian key ships as French. Add the three at once; a parity test is still to write (open item in `MEMORY.md`).
- Long texts: `src/content/{bio,introduction,comparaison,aide}.ts`, one entry per language, typed blocks (`h2`, `p`, `list`, `callout`, `note`, `table`, `steps`, `keys`…) rendered by one component each and by `src/lib/markdown.ts` for the twins. The French is Nabih Gédéon's; English and Italian are marked "traduction de travail" in the files' headers — a translation fix is fine, a rewrite is not.
- `CATEGORY_LABELS` in `src/lib/systemg/library.ts` and the help page (`content/aide.ts`) are the player's own three-language texts; they do not go through `ui.ts`.

## Pages and SEO (2026-10-19)

- **`src/lib/routes.ts` is the manifest.** A route = a neutral path, a page type (`website` · `profile` · `article` · `app`, driving `og:type` and the JSON-LD node) and a `meta(lang)` resolved from the dictionaries. Read by the sitemap, `scripts/build-og-images.mjs`, `src/pages/[...slug].md.ts` (the Markdown twins) and, for the slug of the share image, `Seo.astro`. `llms.txt.ts` lists the main pages by hand from the dictionaries, not from the manifest.
- A page "in preparation" (Literature) is `noindex: true` on the route and `noindex` on the layout: `robots` meta `noindex, nofollow`, out of the sitemap and the twins, but it keeps a share image, because a link to it may still be pasted.
- `BaseLayout.astro` writes the head: title composed as `<page> — <site>`, description, robots, author, canonical, hreflang for the three languages plus `x-default` (French), Open Graph with locale alternates, Twitter card, the Markdown twin as `rel="alternate" type="text/markdown"`, the icons and the manifest. **Trap**: `import.meta.env.BASE_URL` has no trailing slash under a GitHub Pages sub-path (`/system-g`), so every asset path strips a trailing slash from the base and adds its own (`assetBase`), or you get `/system-gfavicon.svg` — the bug of PR #2.
- `SchemaOrg.astro` writes one JSON-LD graph per page: `WebSite` + `Person` (the author, `sameAs` from `authorSameAs()` in `seo.ts`, the one place his public profiles live) + the page's node + a `BreadcrumbList` whose section names come from the nav keys. The author's description on `ProfilePage` is the first paragraph of the biography.
- The sitemap is hand-built (`src/pages/sitemap.xml.ts`), not a plugin, to carry `lastmod` from git (`src/lib/git.ts`, one `git log -1` per page, cached) and each page's share image. `robots.txt` names the AI crawlers one by one and allows them all — a deliberate choice stated in the file: visibility of the theory is the point, training and citation alike. Do not add a blanket `Disallow`.
- Share images: one per page and language, 1200 × 630, `public/og/<lang>/<slug>.png`, drawn by `scripts/build-og-images.mjs` before every build (`prebuild`) with satori and EB Garamond's own font files (`@fontsource/eb-garamond`, a dev dependency used for nothing else) rasterised by `@resvg/resvg-wasm`. **Why not sharp**: it resolves fonts by name through the machine's font config and renders the text invisible on a server without the font; the WASM path draws the same pixels everywhere. The folder is gitignored so an image can never lag behind its page's text.
- The Markdown twins (`/theorie/introduction.md`, `/en/index.md`…) are rendered by `src/lib/markdown.ts` from the same content modules as the HTML, served as `text/markdown`; `llms.txt` is generated from the dictionaries. A new content block type needs its Markdown rendering too, or the twin silently drops it.

## Look (2026-10-19)

- One theme, light, "paper / serif / musicology": tokens in `src/styles/global.css` (`--paper`, `--ink`, `--accent` oxblood `#7a2e2e`, `--gold` `#9a7b3f`), system serifs (Iowan Old Style, Palatino, Georgia) with no web font on the pages — EB Garamond is used only to draw the share images. `color-scheme: light` is declared; no dark theme exists and none was asked for.
- The `♮` natural sign is the site's mark (header, hero, footer, the favicon); it is a text glyph on the pages, drawn by whatever serif the visitor has.

## Measurement (2026-10-19, PR #3 and #4)

- Umami, the publisher's instance at `https://insight.steevepommier.com/insight` — the tracker is served under `/insight` because filter lists block `/script.js`. `src/lib/audience.ts` computes the build's settings (`AUDIENCE_DEFAULTS`: tracker, site id `fc7bac2a-…`, allowed hosts `intervalles-systeme-g.com` and `costardrouge.github.io`); `Audience.astro` writes them as a JSON block in the head, **no `preconnect`** (that alone would reach the server for a visitor who refuses); `src/lib/audience-client.ts` loads the tracker unless Do Not Track, Global Privacy Control or the `umami.disabled` key in `localStorage` says no. Auto-track is fine here because every page is a full load; `excludeSearch` and `excludeHash` are set. No event is sent by hand.
- Only a production build measures (`import.meta.env.PROD`), unless `UMAMI_DEV=true`; an empty `UMAMI_WEBSITE_ID` writes nothing in the pages at all (`UMAMI_WEBSITE_ID= npm run build`); `UMAMI_SRC` and `UMAMI_DOMAINS` override the instance and the hosts. A host not in the list (localhost, a fork) loads the tracker but is never counted.
- The site id is in the code on purpose (PR #4): it ends up in every page anyway, and the deploy needs no variable. The footer line (`footer.audience`) appears only in a build that measures (`Footer.astro` calls `audienceSettings` at build time).
- The `README.md` "Mesure d'audience" section is the visitor-facing description in French; keep it true when the loading rules change.
