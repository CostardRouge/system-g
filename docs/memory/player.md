# The interactive player: the port of the G System Player

Read before touching `src/lib/systemg/`, `src/components/GPlayer.astro`, `PositionsExplorer.astro`, `PlayerHelpPanel.astro`, `public/player/`, `scripts/build-library.mjs` or `system-g-player/`. The design record is `docs/plan-portage-player.md` (2026-07-07); this file holds what the build taught.

## What is being ported (2026-10-19, from the plan and the sources)

- The legacy is a 2009 C# WinForms application by Faraj Elias (its sources carry his copyright notice) built for Nabih Gédéon: ~1 150 useful lines (`FormG.cs`, `BeepCl.cs`) plus an expression DLL. Two trees under `system-g-player/`: "G System player code source" (instruments embedded, **the reference for the port**) and "_Users" (instruments through the Windows registry). Never edit anything under `system-g-player/`: it is the archive the port is measured against.
- Three bricks, all kept: **scale files** (`gamme occidentale.txt`, 485 lines, A = 441 Hz; `gamme orientale.txt`, A = 440 Hz) where every note is an exact fractional expression of the A (`SOLG3 = SOLG*896/891`, the `1`/`3` suffixes being the Système G's positions) and durations are symbols (`N = 800`, `B = 2*N`, triplets, quintuplets, dotted); **score files** (`@gamme`, local redefinitions, `$ instrument`, `#` comments, one `note,duration` pair per line, monophonic); **a monophonic audio engine** with sampled instruments or an oscillator.

## Decisions (2026-10-19, read off the code)

- **Pure TypeScript island, no framework**: `src/lib/systemg/` (`scale-parser`, `score-parser`, `evaluator`, `engine`, `instruments`, `temperament`, `wav-export`, `library`) imports no DOM; `GPlayer.astro` is the one DOM-bound file. The evaluator resolves symbols recursively and computes in **exact rationals** (numerator/denominator) so no rounding drifts from the legacy's values; errors carry the line number, as the legacy reported them. Keep the engine DOM-free and tested.
- **Fidelity over taste.** The tests under `src/lib/systemg/__tests__/` pin values the legacy computed (frequencies, durations, the 18 coefficients); a change that moves one is a bug or a documented correction of the legacy, said in the commit body. Legacy semantics kept on purpose: monophony, every note restarts its sample from the start, **no sample looping** (`PlayFlags = 0` in the legacy, so a sample shorter than its note dies out), frequency 0 (`P`) is silence, `$ instrument` lines switch the instrument unless "force instrument" is on, transposition is an additive offset on the instrument's coefficient.
- **Pitch by resampling, as the legacy did**: `playbackRate = Hz × coefficient / wavSampleRate`; the coefficients come from `FormG.cs`, the sample rates were **measured on the original WAV files** and must stay the files' own (`decodeAudioData` resamples to the context's rate while keeping the pitch). The 18 samples are served as the original WAVs under `public/player/` (~4.8 MB, the fidelity choice of the plan's question 2).
- **Better than the legacy only where the web is better**: scheduling on `AudioContext.currentTime` with a lookahead instead of `Thread.Sleep`, short gain envelopes against the clicks, exact pause/resume through `suspend()`/`resume()`.
- **Phase 3 is built** (0.3.0 "Citrine"): the A/B comparator plays a passage in just intonation then snapped to 12-TET on the same A (`temperament.ts`: `snapToEqual`, `centsFromEqual`), a score editor validated line by line, a WAV export through `OfflineAudioContext`, a pitch curve against equal temperament, and the positions explorer (`PositionsExplorer.astro`, `/theorie/positions`: one octave, every position at its exact frequency against the twelve tempered semitones, gold = above, red = below).
- **Scores stay the original `.txt`**, the archive's canonical format; `scripts/build-library.mjs` (run by hand, idempotent) copies each legacy file to `public/player/scores/<slug>.txt`, unwraps simple RTF, and writes `src/lib/systemg/library.json` (title, composer from a prefix table, category `repertoire` · `vaccai` · `varietes`). Never edit `library.json` by hand; a new score goes into the legacy folder and the script runs again. A dropped `.txt` file plays too (File API).
- **Settings on the device only**: the player keeps mode, instrument, tuning, tempo, transposition and follow in `localStorage` under `systemg.player.settings` (invalid values fall back to defaults); nothing leaves the browser. Say so in the legal notice when one exists.
- The AudioContext starts on a user gesture (Play), the standard autoplay rule; the help page (`/player/aide`, `content/aide.ts`) and the folding panel above the player document the keys and the score format in three languages.

## Open (2026-10-19)

- The plan's question 1 (a framework if phase 3's UI grows) was answered by building phase 3 in plain TypeScript; `GPlayer.astro` is ~50 kB of one script and will want splitting before any further feature.
- Not measured on a phone from a session: the sample loading time and the audio latency.
